## 概要

現在のグローは [GlowShaders.metal](../../Sources/Processing/GlowShaders.metal) の `extractStars` で背景を減算してから星を取り出すため、天の川の「面としての明るさ」は設計上グロー源から外れている。
このため星は光っても天の川そのものは持ち上がらない。背景減算をせず、天の川の面輝度自体をグロー源にする新しいレイヤー種別を追加する。

明るさ下限を空の背景レベル付近に置くのが要点。下限なしでは空も一緒に浮いてコントラストが落ちる（実測: 天の川/空の比が 2.35 → 2.25 に低下）。下限を入れると天の川だけが持ち上がる（比 2.79 へ上昇）。

- **対象**: 面グロー（`GlowLayerKind.area`）レイヤー種別の追加。既存の星グローとは独立したレイヤーとして重ねる
- **やらないこと**: 既存の星グローの挙動変更、グロー半径の上限拡大（現行 200 で足りることを検証済み）、トーンカーブ的な明るさ調整機能
- **関連**: [技術仕様.md](../技術仕様.md) / [UI.md](../UI.md) / [実装計画.md](実装計画.md)（本体・別台帳）/ [実装計画-プリセット保存.md](実装計画-プリセット保存.md)（別台帳）

```bash

JPSTELLAVEIL_ADD_AREA_GLOW=1 \
JPSTELLAVEIL_AREA_FLOOR=0.01 \
JPSTELLAVEIL_AUTO_APPLY=1 \
```

**ペンディングの理由**: 明るさ下限が linear の絶対値なので、画像の露出で適正値が桁違いになる。現像済み画像は空が linear 0.057 で既定の 0.05 が妥当だが、未現像 TIFF は空 0.011 / 明部 0.036 しかなく、既定値ではほとんど光らない（実測で天の川側 ×0.99）。この状態でプリセットを作っても、保存した下限の値が別の写真で意味を持たない。

**再開するときの最初の判断**: 下限を絶対値のままにして既定値だけ直すか、「上位何％を光らせるか」の指定に変えるか。後者なら `GlowStarHistogram.fraction(atOrAbove:)` の逆関数を作れば実装でき、露出の違う写真でも同じ意図が伝わるためプリセットが実用になる。

## 注意点

- **空マスクが実質必須**: 背景減算をしないため、マスクなしでは地面や被写体も光る。既存の空マスクをそのまま使う
- **明るさ下限は絶対値**: 入力画像の露出に依存するので、写真ごとの調整が要る。ヒストグラム表示（P2-4）が判断材料になる
- **Screen 合成は 1 で飽和する**: 面グローは星より値が大きくなりやすく、`compositeGlow` の `saturate` に当たりやすい。強度を上げすぎると階調が潰れる
- **4成分 PSF は流用しない**: 芯（σ 0.25 倍）が重み 0.55 を占め、面グローでは広がりが出ない。面グローは単一ガウシアンにする
- **レイヤー数の上限は 8 のまま**: 星グローと面グローを重ねると枠を2つ使う（`GlowPipeline.maximumLayerCount`）

## 付録: 元になった比較分析

この機能は「AstroTool の Glow をかけた写真のほうが天の川が明るい」という観察から出発した。
比較した2枚（`A1_08145-Mean Max Hor Accuracy` の JPStellaVeil 版と AstroTool Glow 版）を解析した結果を残しておく。

**2枚は別々に現像・書き出しされていた**。Exif の ModifyDate が 2026-08-25 02:42 と 2026-08-24 12:36 で1日以上離れ、クロップも違う（3193x5676 と 3205x5697）。同じ素材にグローだけを変えた比較ではない。

**明るさの差の大半は現像トーンで説明できる**。アフィン変換で位置を合わせてトーン伝達関数を推定すると、面成分の 86% が単調なカーブで説明できた。倍率は暗部 ×3.4、中間 ×2.2、天の川コア ×1.2 で、グローが届かないはずの前景の草原が最も明るくなっている（×3.8）。

**天の川と空のコントラストはむしろ下がっていた**（2.41 → 1.68）。天の川が明るく見えるのは全体が持ち上がって淡い部分が見えるようになったためで、天の川を選択的に強調した結果ではない。

**「天の川だけを強調する処理」の証拠は取れなかった**。カーブで説明できない残差は一見天の川の形に見えるが、大局的な上下トレンドを除くと局所効果は 2/255 程度に縮み、星密度による説明も消えた（相関 r = +0.40 → +0.06）。

ただし JPStellaVeil 側に天の川が光らない構造的な理由は確かにある（`extractStars` の背景減算）。面グローはそこを埋めるために設計した。
**同じ現像から Glow の有無だけを変えた2枚**が用意できれば、AstroTool のグロー自体の寄与を正確に測れる。再開するならまずそれを揃えるとよい。
